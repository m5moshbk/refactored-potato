# M5mOsH Voice Nexus — صدى الحرف

**Voice • Identity • Access • Future**

منصة عربية تضع التواصل وإمكانية الوصول في مقدمة التجربة، وتبني أساسًا آمنًا للتعامل مع الصوت والهوية الرقمية.

> الصوت ليس مجرد وسيلة للتواصل. الصوت هو التعبير، والوصول، والمستقبل.

## نبذة المنتج

M5mOsH Voice Nexus يجمع بين أدوات الكلام والنص، تحويل النص إلى صوت، ولوحة عبارات مساعدة للأشخاص الذين يواجهون صعوبات في النطق أو التواصل. كما يطوّر أساسًا مؤسسيًا يمكن توسيعه لاحقًا إلى خدمات الهوية الصوتية بعد استكمال التقييمات الأمنية والبيومترية اللازمة.

## الحالة التقنية الحالية — 2026-10-31

| المجال | الحالة الحالية |
|---|---|
| الواجهة العربية RTL | موجودة في `sada-voice/frontend` |
| كلام إلى نص | يعتمد على دعم Speech Recognition في المتصفح |
| نص إلى صوت | يعتمد على Speech Synthesis في المتصفح |
| لوحة العبارات السريعة | متاحة في الواجهة |
| حسابات المستخدمين | API أولي مع JWT وتجزئة كلمات المرور |
| تحويل صوت على الخادم | غير مفعّل |
| بصمة/تحقق هوية صوتية | معطّل عمدًا؛ لا يوجد نموذج بيومتري معتمد |
| لوحة المؤسسات | غير منفذة بعد |
| قاعدة البيانات | SQLAlchemy؛ يلزم إعداد قاعدة بيانات ومخططات ترحيل قبل الإنتاج |
| الجاهزية الإنتاجية | غير جاهز للإنتاج |

هذه الحالة وصف لما هو موجود في الشيفرة، وليست شهادة جودة أو اختبار نشر.

## بنية المستودع

- `sada-voice/backend/`: خدمة FastAPI، المصادقة، حدود واجهات الصوت، وتقييم الجاهزية.
- `sada-voice/frontend/`: واجهة Next.js عربية ومتجاوبة.
- `sada-voice/docker-compose.yml`: بيئة PostgreSQL محلية.
- `M5mOsH-Voice-Nexus.md`: تعريف المنتج وخارطة الطريق.
- `M5mOsH-Complete-Brand-Pack.md`: الهوية والنبرة والرسائل.
- `PROJECT_AUDIT.md` و`WORKLOG.md`: سجلات تدقيق/عمل تاريخية، وليست مراقبة حية.
- `telegram_bot/` وملفات HTML الأخرى: محفوظة كما هي؛ لم تُنقل أو تُحذف لعدم ثبوت أنها ملفات قديمة غير مستخدمة.

## التشغيل المحلي

### Backend

```bash
cd sada-voice/backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

أنشئ قيمة عشوائية طويلة لـ `SECRET_KEY` داخل ملفك المحلي، ثم شغّل:

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend

```bash
cd sada-voice/frontend
cp .env.example .env.local
npm install
npm run dev
```

الواجهة تستخدم `NEXT_PUBLIC_API_URL` للاتصال بالخادم. لا تضع أسرارًا في أي متغير يبدأ بـ `NEXT_PUBLIC_`.

## واجهات API الحالية

- `GET /health`: حالة خدمة API والقدرات المعلنة.
- `POST /api/v1/signup`: إنشاء حساب.
- `POST /api/v1/login`: تسجيل الدخول.
- `GET /api/v1/me`: بيانات الحساب الحالي (Bearer token).
- `POST /api/v1/transcribe`: محمي بالمصادقة؛ يوضح أن التعرف الصوتي على الخادم غير مهيأ.
- `POST /api/v1/voiceprint` و`POST /api/v1/verify`: غير متاحين حتى بناء نموذج بيومتري ومقاومة انتحال وتقييمه.
- `GET /api/v1/evolution`: تقييم حتمي للفجوات والإعدادات؛ لا يعدّل الشيفرة أو الإعدادات تلقائيًا.

## الخصوصية والأمان

- لا يبدأ الميكروفون إلا بعد إجراء المستخدم وموافقته في الواجهة.
- خدمة التعرف في المتصفح قد تعتمد على مزود المتصفح؛ راجع سياسة الخصوصية الخاصة به قبل الاستخدام.
- لا تُرفع تسجيلات الميكروفون إلى خادم المشروع بواسطة ميزة التعرف الحالية.
- لا تُخزّن ملفات الصوت الخام افتراضيًا.
- لا تعتبر SHA-256 لملف صوت بصمة متحدث أو دليل هوية.
- لا تُفعّل المصادقة الصوتية قبل الموافقة الصريحة، ونموذج متحقق، واختبارات مقاومة إعادة التشغيل والتزييف، وسياسة حذف وتشفير.
- لا تستخدم هذه النسخة لاتخاذ قرارات طبية أو قانونية أو أمنية حساسة.
- لا تضع كلمات مرور أو مفاتيح أو عناوين قواعد بيانات حقيقية في Git.

## حدود النشر

هذه نسخة أساس تطويرية وليست إصدارًا إنتاجيًا. قبل النشر العام يلزم على الأقل:
1. إعداد قاعدة بيانات دائمة ومخططات ترحيل.
2. اختبار تسجيل الحسابات والجلسات وحدود الصلاحيات.

5. اختبارات تكامل وأمان وإمكانية وصول على بيئة staging.
6. اختيار محرك كلام مناسب من حيث الترخيص والتكلفة والخصوصية.
7. تطوير لوحة المؤسسات وعزل بيانات كل مؤسسة.
